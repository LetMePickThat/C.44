SPACE AESA RADAR -- MISSION PREPARATION AND OPTIMISATION TOOL (V1)
======================================================================

This folder holds the project's reference documentation. The executable tool
is in the V1/ subfolder.


1. WHAT THE TOOL DOES
----------------------
The operator defines the mission (watch sectors: angular zone, target RCS,
required range, refresh rate RR, closing speeds), sees the matching radar
coverage in a real-time 3D view, validates the mission preparation, then runs
the optimisation. For each sector the tool proposes the least energy-hungry
waveform that reaches the required range, and gives the resulting radar
budget per face (energy, average power, time on air).


2. REFERENCE DOCUMENTATION (at the root, outside V1/)
------------------------------------------------------
- PROJECT_CONTEXT.md     : full project summary, decision history.
- radar_params_restore.md : all locked / open radar parameters.

3. MODULES IN V1/
------------------

Radar engine (supplied, logic unchanged):
  WF_RANGE_CALC_V6.0.10.py
      Full radar model: S/Ku bands, losses, radar equation, face geometry,
      beam-position lattice. Contains the non-regression "selftest"
      (python WF_RANGE_CALC_V6.0.10.py --selftest).
      Only change: the sector area (sector_area_uv) is cached, which made
      the optimiser more than 100x faster without changing any result.
  mission_optimizer.py
      Pre-mission optimiser (v2): for each sector, picks one waveform per
      5-degree scan-angle bin (at most 4 distinct waveforms per sector,
      option "max_wf_per_sector"), each just reaching the required range,
      so as to minimise max(energy, time on air) of the faces. Computes the
      per-face budget (energy %, time on air %, kW), the achieved RR and
      the tracking margin (power left for Ku per face, with the
      equivalent Ku duty cycle). A frequency that leaves more of the
      sector unscanned (2.9 GHz: 70-degree scan limit) is never preferred.
      This is the EXACT calculation (under a second for the example
      mission). From 6 sectors up, sectors are spread over parallel
      worker processes (started on the first such run, then reused for
      the session), and radar-equation results are cached between runs.
  gen_cost_table.py
      Generates cost_table.json: a precomputed table (range x RCS x speed
      x scan angle) used for the FAST estimate in window 1. Rerun only if
      the radar model changes (python gen_cost_table.py, about 2 seconds).
      Its energies agree with the exact optimiser within a few %.

Modules written for the tool:
  geometry.py
      Single source of the 3D geometry: ship frame, position of the 4
      faces, responsibility zones, PyVista mesh builders (sphere, coloured
      sectors, ship, axes, normals). Reuses the same formulas as
      WF_RANGE_CALC so it never drifts from the radar model.
  cost_estimate.py
      FAST, approximate per-face budget (energy %, average power) by
      interpolation in cost_table.json. Used for the real-time gauges while
      editing, NOT for the final result (which comes from
      mission_optimizer.py).
  mission_data.py
      Mission sector model, mission-prep validation (unique ids, bounds,
      field consistency), JSON and CSV import/export.
  optimize_worker.py
      Runs mission_optimizer.py on a separate thread (progress bar,
      cancel) so the interface does not freeze during the exact
      calculation.
  mission_prep_window.py
      WINDOW 1: sector form + real-time 3D view + per-face gauges +
      alerts + "Validate mission prep" button + "Run calculation" button.
  view_controls.py
      Display bar shared by both 3D views (show / hide the responsibility
      zone of each face, show / hide all mission volumes).
  results_window.py
      WINDOW 2: 3D view coloured by result (achieved/target RR or energy %)
      + summary tables + JSON/CSV export of the result.
  main.py
      Single entry point (see section 5): without arguments, a small
      launch window with "New mission" / "Open a mission..." (file
      dialog); with a mission file, opens it directly.

Data:
  cost_table.json        : precomputed table (see gen_cost_table.py).
  mission_example.json / mission_example.csv
      Example mission (3 made-up sectors) to try the tool.
  mission_report.json
      Matching example result (generated by mission_optimizer.py).
  mission_veille500.json
      Optimiser v2 test mission (forward cone + KV search), reconstructed
      from AUDIT/SPEC_optimiseur_v2.md.


4. INSTALLATION
----------------
Python dependencies (once):
  python -m pip install pyvista pyvistaqt PyQt5 numpy

(scipy is not needed, although it is common in this kind of tool.)


5. STARTING THE TOOL
---------------------
From the V1/ folder:

  python main.py
      Opens the launch window: "New mission" or "Open a mission..."
      (JSON/CSV file dialog). Recommended, no path to type.

  python main.py mission_example.json
      Opens the supplied example directly (handy to discover the tool).
      Same with a CSV. If the file cannot be read, an error is shown
      and the launch window opens instead.

  python main.py --new
      Starts an empty mission directly.


6. USAGE
---------
Window 1 - Mission preparation:
  1. Set the global scan zone (eps_min / eps_max, power per face) at the
     top of the right-hand panel.
  2. Add watch sectors (+ Box for a rectangular phi/eps zone, + Cap for a
     circular zone), duplicate or delete them.
  3. Select a sector in the list to edit its fields (RCS, required range,
     target RR, min/max closing speeds...). The 3D view and the per-face
     gauges update automatically (a few hundred ms after the last change).
  4. Watch the gauges (energy %, time on air -- approximate lower bound)
     and the "Alerts" panel (overlapping sectors, zones outside coverage,
     over-subscribed face).
  5. Import / export the mission as JSON or CSV if needed.
  Display (both windows): the bar above the 3D view shows / hides each
  face's responsibility zone (F1-F4 check boxes) and all mission volumes
  at once; each sector's own check box (in the sector list, or in the
  first column of the results summary table) shows / hides its volume.
  6. Click "Validate mission prep" to check consistency (unique ids,
     bounds, min speed <= max speed, range and RR > 0...).
  7. Click "Run calculation": runs the EXACT calculation on a separate
     thread, with a cancellable progress bar. When it finishes, the
     results window opens automatically.

Window 2 - Results:
  - Choose in the drop-down list the quantity used to colour the sectors:
    achieved/target RR, energy % of the sector alone (worst face), or
    total energy % of the most loaded face it uses (green up to 70 %,
    amber up to 100 %, red when the face is over-subscribed).
  - If the calculation was cancelled, you are asked whether to open the
    partial result; a red banner then marks it as PARTIAL.
  - The 3D labels give, per sector, the selected waveform, the ranges
    reached (worst and best scan angle), the RRs (target / alone / in
    mission) and any infeasibility flags.
  - The summary table and the per-face totals (with the tracking margin)
    are in the right-hand panel. Select a sector in the summary table to
    see its waveforms by scan-angle bin.
  - Export the full result as JSON, or the summary as CSV.

Faces are labelled F1 to F4 (phi = 0, 90, 180, 270 deg).


7. IMPORTANT NOTE
------------------
The "energy %" gauges in window 1 are a fast estimate (typically a few %
off). The "time on air" shown in window 1 is deliberately only a LOWER
BOUND (the exact time depends on the waveform shared across the whole
sector, which only the exact calculation determines). Only the result in
window 2 (after "Run calculation") is authoritative.
